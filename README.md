# Мастерская партий R Prison

Локальное приложение для мастера настольной ролевой игры. Итерация 11б: карточки персонажей и проведение боя с инициативой, ходами и раундами. Доступны независимые партии, карты PNG/JPG, камера, сдвиг сетки мышью и помощник физического масштаба. Добавлены персонажи, NPC и токены с портретами. Добавлены разметка карты и предметы на поле. Атаки и эффекты пока не автоматизированы.

## Запуск

Требуется Node.js 24 LTS и npm. В терминале из каталога проекта:

```sh
npm ci
npm test
npm run build
npm start
```

Для разработки с пересборкой перед запуском: `npm run dev`. После изменения исходников перезапустите команду. Автоматического обновления пока нет.

## Навигация

При запуске выберите «Создать партию» или «Открыть партию…». После входа формы выбора скрываются, остаются название партии, сохранение и вкладки:

- **Карты** — импорт, сетка, масштаб, разметка, поле и токены.
- **Способности** — каталог, назначения и ручные счётчики.
- **Инвентари** — иконки владельцев, поиск и перетаскивание снаряжения.
- **Предметы** — шаблоны, выдача, инвентарь и индивидуальное состояние вещей.
- **Правила** — показатели, формулы, проверочный расчёт.
- **Персонажи** — создание карточек, портреты, характеристики и каталог. «На карту: имя» автоматически открывает вкладку «Карты» в режиме размещения.

Вкладки сохраняют незавершённый ввод при переключении в пределах текущей партии. Стрелки влево/вправо на заголовке вкладки переключают раздел. «К выбору партии» возвращает на стартовый экран; при несохранённых изменениях сначала появляется предупреждение. Подтверждение отбрасывает несохранённые изменения. «Открыть партию…» в верхней панели позволяет сразу выбрать другой файл; отмена или ошибка сохраняет текущую партию.

Формат данных не менялся — v6.

## Ручная проверка

1. Создайте партию «Побег из Лейквью».
2. Нажмите «Сохранить как…», выберите JSON-файл.
3. Закройте приложение, запустите `npm start`, откройте файл: название должно восстановиться.
4. Создайте другую партию, сохраните другим файлом: первая должна остаться независимой.
5. Попробуйте открыть повреждённый JSON: должно появиться сообщение об ошибке, текущая партия должна сохраниться в окне.
6. Отмените системный диалог: текущая партия не должна измениться.

Windows — первая целевая платформа. Сейчас запускается распакованная версия через Electron; установщик будет позже. Проверки в Linux не заменяют проверку на Windows.

Формат JSON v14 содержит изображения, калибровку сетки и отдельное состояние камеры для каждой карты. Старые партии v1/v2/v3/v4/v5/v6/v7/v8/v9/v10/v11/v12/v13 открываются автоматически; при сохранении создаётся v14, который старые версии приложения не откроют. Перед обновлением сохраните копию старого файла.

## Карты (итерация 2)

1. Создайте или откройте партию, нажмите «Добавить карту…», выберите PNG/JPG.
2. Прокрутите ниже до поля карты. Колесо мыши меняет масштаб относительно курсора; зажатая левая кнопка перемещает карту. «Вписать карту» возвращает её в поле целиком.
3. Добавьте вторую карту и переключайте их через «Текущая карта». У каждой своя камера.
4. Сохраните партию, перезапустите приложение и откройте файл. Обе карты, выбранная карта и положения камер должны восстановиться.
5. Изображения встроены в JSON: исходный PNG/JPG после импорта больше не нужен. Скопируйте JSON в другую папку и проверьте открытие.

Ограничения: до 20 карт, каждая до 15 МБ, до 8192 пикселей по стороне и до 32 млн пикселей. Весь JSON до 100 МБ. Base64 увеличивает размер изображений примерно на треть. Для крупных партий позже предусмотрено отдельное хранилище. Автосохранения пока нет: после импорта и перемещения камеры нажимайте «Сохранить как…».

## Сетка (итерация 3)

1. Выберите карту и включите «Показать сетку».
2. Задайте размер клетки в пикселях **исходного изображения**, а не экрана. Например, если изображение шириной 4000 пикселей содержит 40 клеток — размер клетки 100.
3. Подберите смещения X/Y, чтобы линии совпали с картой, и нажмите «Применить сетку». Дробные значения допустимы. Положительное X сдвигает начало вправо, положительное Y — вниз. Сетка повторяется в обе стороны от начала.
4. Приближайте и перемещайте карту: линии должны оставаться на тех же местах изображения.
5. Сохраните партию. После повторного открытия размер клетки, смещения и видимость восстановятся. У другой карты настройки независимы.

Размер клетки: 4–4096 пикселей; смещения: −8192…8192. При размере клетки на экране менее 6 пикселей линии временно не рисуются: приблизьте карту. Это не меняет калибровку. Сетка ограничена изображением; поворот и привязка токенов пока не реализованы.

## Перемещение и масштаб локации (итерация 4)

- Включите «Перемещать сетку» и тяните её левой кнопкой мыши. Карта остаётся на месте. Снимите галочку, чтобы снова перемещать карту. Колесо по-прежнему меняет масштаб просмотра. При включении режима скрытая сетка становится видимой.
- Выберите визуальный пресет и нажмите «Подобрать размер». Дом предлагает 12 клеток по короткой стороне и 1 м/клетку, лес — 40 клеток и 5 м/клетку. Число клеток и метры можно изменить. Размер в пикселях вычисляется по размерам изображения (с ограничением 4–4096).
- Это начальные редактируемые предложения, **не автоматическое распознавание изображения** и не правила расхода ОД. Тип применённого пресета и метры сохраняются отдельно для каждой карты. Режимы инструментов не сохраняются.
- Для точной подгонки сначала укажите «Метров на клетку» и нажмите «Применить сетку». Затем нажмите «Калибровать по отрезку», щёлкните две точки изображения, укажите известное расстояние между ними в метрах и нажмите «Применить отрезок». Например: отрезок 10 м, клетка 5 м — между точками получится длина двух клеток. Первая точка станет началом сетки; сетка не поворачивается.
- Повторный третий щелчок начинает выбор заново. Кнопка отмены выходит из инструмента без изменения калибровки. Точки вне изображения не принимаются.
- Старые карты не содержали физического масштаба: им предлагается 1 м/клетку с подсказкой. Проверьте это значение перед измерениями. Диапазон — 0.1–1000 м/клетку.
- После изменений сохраните JSON. Новая версия открывает v1–v5, сохранение пишет v6. Сохраните резервную копию прежнего JSON: старое приложение новый v6 не откроет.

## Персонажи и токены (итерация 5)

1. В открытой партии в блоке «Персонажи и NPC» введите имя, тип и размер **ширина × высота** от 1 до 10 клеток. Необязательно выберите портрет PNG/JPG. Нажмите «Добавить персонажа».
2. Выберите карту, нажмите «На карту: имя», прокрутите к полю и щёлкните **верхнюю левую клетку** занимаемой области. Вся область должна помещаться на изображении и быть свободной. При ошибке выбор персонажа остаётся активным — попробуйте другую клетку. «Отменить размещение» выходит из инструмента.
3. Перетаскивайте круглый токен: после отпускания он привяжется к сетке. Стрелки на выделенном токене перемещают его на клетку. Пунктир показывает всю занимаемую область; у прямоугольного персонажа круглый портрет расположен по центру.
4. «Убрать токен: имя» или Delete убирает только выбранный токен. Персонаж остаётся в каталоге, его можно снова поставить на любую карту. Можно создать несколько токенов одного персонажа.
5. «Удалить: имя» с подтверждением удаляет персонажа **и все его токены на всех картах**.
6. Сохраните партию и откройте после перезапуска: каталог, портреты, размеры и положения должны восстановиться.

Каталог пока принадлежит партии: перенос между партиями и общий каталог будут позже. Токен и персонаж — разные объекты. Редактирование уже созданной карточки, характеристики, HP, предметы, эффекты, бой, расход ОД и поиск пути пока не реализованы. Сейчас проверяются только конечная клетка, занимаемая область, границы и занятость. Ручное движение может пересекать будущие препятствия.

Пределы: 200 персонажей, 500 токенов на партию. Портрет до 15 МБ (PNG/JPG), до 8192 пикселей по стороне и 32 млн пикселей; при импорте уменьшается до 512 пикселей по большей стороне и сохраняется внутри JSON. Оригинал не меняется и для открытия партии больше не нужен. Изменение калибровки сетки двигает токены вместе с клетками и отклоняется, если они выходят за карту. Сначала калибруйте карту, затем размещайте персонажей.

Сохранение теперь пишет v6. Старые v1–v5 открываются, но прежняя версия приложения v6 не откроет. Держите копии прежних файлов.

## Разметка карты (итерация 6)

1. В блоке «Разметка карты» выберите инструмент: **Стена**, **Укрытие**, **Высота**, **Жидкость** или **Свет**.
2. Укажите название и параметры. Для стены можно включить «Разрушаемая стена» и задать прочность (это пока только данные). Для укрытия — степень, для высоты — метры относительно условного нуля карты, для жидкости — тип.
3. Щёлкните две точки на изображении и нажмите «Добавить разметку»:
   - стена: начало и конец произвольного отрезка;
   - укрытие, высота, жидкость: противоположные углы прямоугольной области;
   - свет: центр и точка радиуса круглой области.
4. Точки задаются в пикселях исходной карты, без привязки к сетке. Масштабирование и перемещение камеры сохраняют разметку на том же месте. Третий щелчок начинает выбор заново; «Сбросить точки» отменяет незавершённый выбор.
5. Выберите объект из списка или включите «Выбрать разметку на карте» и щёлкните видимую фигуру. Измените свойства → «Сохранить свойства». Для изменения положения/размера нажмите «Заменить геометрию двумя точками», выберите новые точки → «Сохранить свойства».
6. «Скрыть» убирает объект с экрана, сохраняя его в партии. Выберите его из списка для редактирования; «Показать» вернёт отображение. «Удалить выбранное» удаляет объект. Отмены удаления пока нет.
7. Верните инструмент в «Камера и токены» для обычной работы. Сохраните JSON и проверьте открытие после перезапуска.

До 500 объектов на карту. Разметка сохраняется отдельно для каждой карты. Области могут перекрываться. Свет у края обрезается границами изображения, не учитывает стены и не скрывает токены. Стены пока **не блокируют перемещение**, укрытия/высоты/жидкости не меняют броски, урон или ОД. Полигональные области и перетаскивание фигур пока не реализованы; положение меняется через две точки. Новое сохранение — v6, прежние приложения его не откроют. Старые v1–v5 поддерживаются.

## Правила и формулы (итерация 7)

Во вкладке **«Правила»** создаются исходные и вычисляемые показатели. В новых партиях включён готовый набор «R Prison v1.1 — черновик». Для существующей партии нажмите «Использовать R Prison — черновик»; замена непустого набора требует подтверждения. Спорные механики отмечены, набор остаётся редактируемым.

Пример для проверки редактора (не утверждённое игровое правило):

1. Нажмите «Добавить исходный показатель»: ключ `power`, название «Показатель», значение 8.
2. Добавьте вычисляемый: ключ `bonus`, название «Бонус», формула `ceil(power / 3)`.
3. Нажмите «Применить правила». В калькуляторе результат бонуса — 3. Измените пробное значение power на 10: получится 4.
4. Выберите персонажа в «Источник значений», задайте исходные значения и нажмите «Сохранить значения персонажа». Либо откройте вкладку «Персонажи» → «Характеристики: имя» → измените поля → «Применить характеристики».
5. Нажмите «Сохранить как…» для записи партии. После перезапуска правила и значения персонажей восстановятся, производные значения пересчитаются.

Разрешены `+ - * /`, скобки, `ceil`, `floor`, `abs`, `min`, `max`; сравнения `< > <= >= == !=`, логические `&& || !`, `if(условие, да, нет)`. Функции min/max принимают 2–8 аргументов, остальные числовые функции — один; if — три. Условия возвращают 1/0, ноль — ложь. if и логические операторы вычисляют только нужные ветви. Ключи — строчные латинские буквы, цифры и `_`, первая буква обязательна. Дроби с точкой.

Ошибки синтаксиса, неизвестные ссылки, дубли и циклические зависимости не дают применить черновик. Прежние правила продолжают работать. Деление на ноль и переполнение показывают ошибку расчёта для текущих значений. Формулы не выполняют JavaScript и не получают доступ к файлам/сети.

До 64 показателей, формула до 512 символов/256 токенов/128 узлов, вложенность до 32. Исходные значения ±1 млрд; промежуточные результаты ±1 трлн. Правила сохраняются в партии со своим UUID, revision и engineVersion=1; общих автоматических обновлений нет. Удаление/переименование ключа не стирает сохранённые исходные значения персонажа: они перестают использоваться до возврата ключа (до 256 сохранённых ключей на персонажа).

Нажатие «Применить правила» создаёт следующую ревизию текущего снимка, не историю версий. «Сбросить черновик» возвращает применённые правила. Пробные значения и неприменённый черновик не записываются в файл. Отдельный импорт/экспорт пакета правил, кубики, модификаторы, эффекты, текущие ресурсы и боевые действия ещё не реализованы. Расчёт показателя с ключом hp не изменяет текущее здоровье.

Сохранение пишет **v7**. Старые v1–v6 открываются с пустыми правилами и пустыми значениями персонажей; новые файлы прежнее приложение не откроет. Перед обновлением оставьте копии JSON.

## Готовый R Prison и видимые характеристики

Формулы вручную писать необязательно. Новая партия использует «R Prison v1.1 — черновик»:

- Сила, Ловкость, Телосложение, Харизма — начальное предложение по 5 (в сумме 20), уровень 1, броня 0. Проверки распределения 20 очков и ограничений создания пока не реализованы.
- Максимум HP: `(constitution + level) * 2 + armor`.
- Максимум ОД: `5 + ceil(dexterity / 3)`.
- Бонус ближнего/дальнего урона: `ceil(strength / 4)` / `ceil(dexterity / 4)`.

Характеристики вводятся уже при создании персонажа/NPC. В карточках всегда видны исходные и рассчитанные показатели; «Характеристики: имя» позволяет их изменить. Это **максимумы**, а не учёт текущих/оставшихся HP и ОД.

Для старой партии: вкладка «Правила» → «Использовать R Prison — черновик» → проверьте значения существующих персонажей → сохраните. Старые значения сохраняются по ключам, но ключи произвольных правил вроде body не переименовываются автоматически в constitution. Отредактируйте соответствующие поля вручную.

В «Правилах» раскройте «Готовые примеры урона и защиты R Prison v1.1». Там калькуляторы ближнего/дальнего урона и попадания с ручным вводом результатов бросков. Это справочные калькуляторы по версии v1.1: они не используют персонажа автоматически, не выбирают оружие/цель, не бросают кости, не применяют урон и не списывают ОД. Данные калькуляторов не сохраняются. Противопоставление при ничьей/реакции требует решения мастера; полное укрытие запрещает выстрел независимо от числа в калькуляторе.

Броня в готовом наборе добавляет HP по v1.1, не поглощает урон. Противоречие с перками, различия урона оружия и стоимость ничьей остаются открытыми вопросами. Формат JSON остаётся v7; существующие партии не изменяются при открытии автоматически.

## Предметы и снаряжение (итерация 8а)

1. Откройте вкладку **«Предметы»**, создайте шаблон: название, категория, описание, максимумы прочности/зарядов. Для оружия укажите кости, например `1d6` или `2d6+1`. Это данные, автоматического броска пока нет.
2. В «Кому выдать новый экземпляр» выберите персонажа/NPC либо «Общий запас». Нажмите «Выдать: имя» дважды — появятся два независимых экземпляра.
3. В первом измените прочность, нажмите «Сохранить состояние». Второй должен остаться прежним. Прочность/заряды — целые числа от 0 до максимума; нулевой максимум означает, что ресурс не используется.
4. В «Владелец экземпляра» можно передать вещь другому персонажу или в общий запас. При передаче снимается отметка экипировки. В общем запасе экипировать нельзя.
5. Отредактируйте шаблон: новые выдачи используют новую версию, старые вещи сохраняют свой снимок, название и максимумы. Удаление шаблона не удаляет выданные вещи.
6. Откройте «Персонажи»: назначенные предметы видны в карточке. При удалении персонажа его вещи возвращаются в общий запас; отдельное удаление экземпляра требует подтверждения.
7. Сохраните партию и откройте после перезапуска. Проверьте разные состояния двух экземпляров, владельцев и отметки экипировки.

До 200 шаблонов и 1000 экземпляров в партии. Каталог пока локален для партии, нет общего каталога между партиями. Экипировка **не меняет** броню, HP, бонусы или броски: модификаторы снаряжения ещё не реализованы. Способности, перенос персонажей между партиями и проверка совместимости будут отдельным обновлением 8в.

Формат теперь **v8**. Старые v1–v7 открываются с пустым каталогом/инвентарём без изменения прочих данных. Прежнее приложение v8 не откроет — оставьте копии JSON.

## Фото, распределение инвентаря и импорт (8б)

**Фотографии:** во вкладке «Предметы» при создании/редактировании шаблона нажмите «Загрузить фото предмета…». PNG/JPG уменьшится до 512 пикселей. Старые экземпляры сохранят прежнее фото своего снимка; новые получат актуальное. Фото хранятся в JSON, исходный файл после сохранения не нужен. Из-за снимков фото может повторяться в файле — действует общий предел партии 100 МБ.

**Распределение:** вкладка «Инвентари». Сверху выберите иконку персонажа/NPC или общий запас. Под ними находится открытый инвентарь, снизу — источник предметов и поиск по названию/описанию.

- «Шаблоны» — перетаскивание создаёт **новый экземпляр** выбранному владельцу.
- «Вещи в общем запасе» / «Вещи других персонажей и запас» — перетаскивание **перемещает существующий экземпляр**, сохраняя ресурсы. Экипировка снимается.
- Предмет можно добавить и кнопкой, без мышиного перетаскивания. «В запас» возвращает вещь из инвентаря персонажа. Изменение прочности/зарядов и экипировка остаются во вкладке «Предметы».

**Импорт:** откройте [пример JSON](examples/content-template.json), заполните его по [описанию формата](docs/content-format.md), затем во вкладке «Персонажи» или «Предметы» выберите «Выбрать JSON для импорта…». Проверьте список и нажмите «Добавить импорт в партию». Неизвестные ключи характеристик блокируют весь пакет, существующие объекты не меняются. Повторный импорт создаёт копии с новыми идентификаторами. Файл до 10 МБ; встроенные картинки только PNG data URL до 512×512, проще оставить `null`.

Импортируются **персонажи и шаблоны**, а не готовое распределение снаряжения/сцены/правила. Способности и полноценный перенос между партиями остаются следующим этапом. Формат партии теперь **v9**, старые v1–v8 поддерживаются; оставляйте копии перед сохранением. Формат внешнего пакета — отдельный `rprison-content` версии 1, он не равен формату партии.

## Способности и перенос (итерация 8в)

### Способности

Во вкладке **«Способности»** создайте название, описание, памятку стоимости и лимит использований. Ноль означает неограниченное использование. Выберите персонажа/NPC и нажмите «Назначить: имя». Назначение получает собственный снимок шаблона и счётчик.

«Использовать» уменьшает ограниченный счётчик на 1, «Восстановить» вручную возвращает максимум, «Снять» удаляет назначение. ОД, HP, баффы и эффекты **не применяются автоматически**. Изменение/удаление шаблона не меняет уже назначенные способности. Они также видны в карточках персонажей. Удаление персонажа удаляет его назначения, вещи как прежде возвращаются в запас. Пределы: 200 шаблонов и 1000 назначений в партии.

### Персонаж между партиями

1. В исходной партии примените изменения характеристик/инвентаря, затем во вкладке «Персонажи» в блоке **«Персонаж между партиями»** выберите персонажа и нажмите «Экспортировать персонажа…».
2. Получится один JSON-пакет с персонажем, портретом, характеристиками, его вещами и их фото/состоянием/экипировкой, назначенными способностями и оставшимися использованиями. Источник не меняется. Применённые данные можно экспортировать и до сохранения партии, но незавершённые поля редакторов в пакет не входят.
3. Откройте целевую партию, затем «Персонажи» → «Перенести персонажа из файла…». Выберите **пакет персонажа**, а не файл партии или ручной content-template.json.
4. Проверьте имя/количества и совместимость. При различии исходных значений по умолчанию, ключей, типов или формул добавление блокируется. Названия/UUID/ревизии правил не обязаны совпадать; лишние скобки/пробелы в формуле не мешают. Алгебраически похожие, но иначе записанные выражения могут считаться несовместимыми. Автоматического обхода проверки нет.
5. Нажмите «Добавить копию персонажа» и сохраните **целевую** партию. Все идентификаторы копии/вещей/назначений обновятся, правила цели не заменяются. Повторное добавление создаёт ещё одну копию, а не обновляет по имени.

Карты/токены, общий запас и чужие предметы не переносятся. Вещи/способности остаются самостоятельными снимками; в общий каталог шаблонов цели они автоматически не добавляются. Токен нужно разместить вручную. Проверка совместимости относится к текущему вычислительному слою показателей; сюжетный смысл описаний мастер проверяет самостоятельно.

Пакет — `rprison-character`, версия 1, до 20 МБ. Запись атомарная, существующий файл не заменяется при ошибке проверки/превышении лимита. Партии теперь сохраняются в **v10**, старые v1–v9 поддерживаются с пустыми способностями. Ручной формат `rprison-content` v1 по-прежнему поддерживается и не заменяет перенос снаряжённого персонажа.

## Движение и препятствия (итерация 9)

Согласовано: **1 ОД за метр**, диагональ стоит расстояние ×√2. Например, клетка 5 м стоит 5 ОД по прямой и примерно 7.071 ОД по диагонали. Масштаб просмотра на стоимость не влияет. ОД дробные, на экране округляются до трёх знаков; в файле хранится точное число JavaScript.

1. Нажмите «Начать игру» и включите «Тактическое движение (расход ОД)». Выберите токен щелчком. В блоке «Движение» появится остаток ОД, а на поле — зелёные доступные позиции.
2. Подсвечена **верхняя левая клетка** возможного размещения всей занимаемой области. Для большого токена учитываются его ширина и высота.
3. Наведите мышь на клетку или перетащите токен: жёлтая линия показывает найденный путь. Щёлкните клетку либо отпустите токен — он переместится, стоимость спишется из общего остатка персонажа. Стрелки также проверяют путь и расход.
4. Стены, в том числе скрытые и разрушаемые, блокируют путь. Разрушение пока не реализовано: удалите разметку вручную при необходимости. Токены занимают клетки; диагональное срезание углов запрещено. Касание стены краем допускается, пересечение занимаемой областью — нет.
5. Невозможное перемещение не меняет токен и ОД. «Отменить последнее движение» возвращает положение и остаток. Отмена доступна только для последнего движения до другой правки партии; камера её не сбрасывает, после перезапуска история не сохраняется.
6. «Восстановить ОД вручную» возвращает текущий максимум. Можно задать остаток вручную от 0 до максимума. ОД общие для всех токенов одного персонажа, даже на разных картах. Автоматических ходов и восстановления пока нет.
7. Для перемещения камеры снимите выбор токена либо используйте **Alt + перетаскивание пустого места**. Колесо работает как раньше.

**Подготовка сцены:** включите «Расстановка мастера (без пути и расхода ОД)». Она позволяет двигать токены через стены без списания ОД, проверяя только занятость и границы. Это также способ исправить старый токен, оказавшийся поверх стены. После подготовки отключите режим. Размещение нового токена кнопкой «На карту» тоже относится к подготовке и не расходует ОД.

Для R Prison источником служит `ap_max`. Старый готовый набор с той же формулой распознаётся при миграции. В собственной системе откройте «Правила», выберите **«Показатель бюджета движения»** и примените: он должен давать число 0–1000000. Это текущий остаток выбранного ресурса, не отдельная скорость D&D. При уменьшении максимума эффективный остаток ограничивается новым максимумом. При увеличении уже потраченный ресурс автоматически не восстанавливается.

Укрытия, свет, высоты и жидкости пока **не меняют движение**. Ограничение поиска — 20000 позиций; при достижении выводится предупреждение. Не найденная при этом клетка не считается доказанно недоступной: двигайтесь более короткими отрезками или уменьшите расчётный бюджет. Стартовая позиция, уже пересекающая стену, может требовать расстановки мастера.

Формат партии теперь **v11**, старые v1–v10 поддерживаются. Сохраняются текущие ресурсы и настройки движения. Совместимость переносимого персонажа теперь учитывает и настройки движения; старые пакеты при несовпадении могут потребовать повторного экспорта из обновлённой исходной партии. Перед обновлением оставьте копии JSON.

## Обновление на Windows

Закройте приложение. Скачайте свежий ZIP из GitHub и распакуйте в **новую папку**, чтобы старые `node_modules` не смешались с новыми. Файлы партий оставьте отдельно. В новой папке рядом с package.json откройте cmd и выполните `npm ci`, затем `npm run dev`.

Документация: [требования](docs/requirements.md), [архитектура](docs/architecture.md), [правила](docs/rules.md), [вопросы](docs/questions.md), [план](docs/iterations.md).

## Дополнительная функциональная проверка

`npm run test:smoke` запускает настоящее окно Electron, создаёт партию, импортирует PNG/JPG, проверяет видимые пиксели карты, камеру, сохранение и открытие после перезапуска. Системные диалоги в тесте подменяются, операции с файлами настоящие. На Linux требуется графический сеанс или Xvfb. Для изолированного CI: `DISPLAY=:99 CI=1 npm run test:smoke`; только в CI передаётся `--no-sandbox`, обычный запуск сохраняет песочницу.

В облачной среде с Node.js 24 загрузке Electron может потребоваться поддержка предоставленного прокси: `NODE_USE_ENV_PROXY=1 npm ci`. Не отключайте TLS-проверку.


## Подготовка и проведение игры (итерация 10)

Новая партия и старые файлы v1–v11 открываются в **Подготовке**. Здесь настраиваются карты, сетка, геометрия, персонажи, правила, шаблоны предметов и способностей; доступны импорт и перенос. Расстановка токенов в подготовке проверяет границы и занятость, не проверяет путь и не тратит ОД.

Когда готово хотя бы одно поле, нажмите **«Начать игру»**. В режиме игры:

- «Поля» переключает подготовленные карты. Доступны просмотр, камера, размещение и перемещение токенов.
- «Персонажи» показывает характеристики, снаряжение и кнопку размещения. Создание и редактирование остаются в конфигураторе.
- Инвентари, выдача/передача предметов, состояние экземпляров и ручные счётчики способностей работают во время игры.
- Редакторы правил, сетки, геометрии и каталогов скрыты. **«Открыть конфигуратор» → «Вернуться в игру»** позволяет внести правки без сброса позиций, инвентарей, ресурсов и счётчиков.

Игра начинается со свободного движения: стены и занятость проверяются, ОД не расходуются, нулевой остаток не мешает движению. **«Тактическое движение (расход ОД)»** включает существующий расчёт стоимости; переключение не восстанавливает ресурс. Расстановка мастера позволяет обойти стены без расхода. Это ещё не бой: очередь ходов, инициатива и автоматическое восстановление не реализованы. В итерации 11а также добавлены предметы на поле — см. ниже.

Формат партии **v12** сохраняет факт начала игры и переключатель тактического движения. Запущенная партия после открытия возвращается в игру. Открытый экран конфигуратора — временное состояние интерфейса. Старые файлы мигрируют без изменения исходников и без сброса текущих ресурсов; перед сохранением в новом формате оставьте копию JSON. Переносимый персонаж и формат контента не меняются.


## Предметы на поле (итерация 11а)

В подготовке и игре у поля появился блок **«Предметы на поле»**:

1. Создайте/выдайте экземпляр во вкладке «Предметы», затем выберите его в списке «Вещь для размещения». Поиск учитывает название и описание; список показывает владельца и короткий ID для одинаковых вещей.
2. Нажмите **«Разместить предмет на поле»**, затем щёлкните целую клетку внутри карты. Вещь уйдёт из инвентаря/запаса, экипировка снимется. Фото, снимок шаблона, прочность и заряды сохранятся.
3. Маркер можно перетаскивать мышью или двигать стрелками при фокусе. Альтернатива — кнопка **«Переместить на поле»** в списке и щелчок по новой клетке. Передача между полями: верните в запас, переключите поле и разместите снова.
4. Выберите **«Получатель предмета с поля»** и нажмите **«Передать с поля»**. Для возврата в запас выберите «Общий запас» или нажмите Delete на маркере. Удаления экземпляра не происходит. В общем списке «Предметы» также видно поле и можно сменить владельца.

Это действия мастера: без проверки дистанции до персонажа, расхода ОД и автоматического подбора. Вещи не блокируют путь и могут лежать друг на друге/под токеном. Если маркеры перекрываются, используйте список под заголовком «Предметы на поле». Маркеры показывают фото либо значок; масштаб и камера синхронны с картой. При смене калибровки сетки координаты остаются клеточными; правка отклоняется, если предмет оказался за границей — сначала перенесите его в запас.

Партия сохраняется в **v13**. Для v1–v12 размещение отсутствует по умолчанию, инвентари и начатая игра сохраняются. Старый JSON при открытии не перезаписывается; перед сохранением новой версией оставьте его копию. Пакеты персонажей не содержат предметы, оставленные на поле.


## Карточка персонажа и бой (итерация 11б)

В игре нажмите на токен: рядом с картой открывается карточка с портретом, характеристиками, текущими **HP/ОД**, инвентарём с фото и назначенными способностями. Кнопка «Карточка» в очереди боя открывает персонажа и без токена на текущем поле. «Закрыть» скрывает карточку; на узком окне она располагается под картой.

Введите остаток и нажмите «Задать HP/ОД» либо восстановите ресурс до максимума. Принимаются конечные числа от нуля до максимума, ОД могут быть дробными. Если остаток ещё не записан, он считается полным; при уменьшении максимума отображается ограниченный остаток, исходный файл при чтении не меняется. Ручное восстановление записывает текущий максимум, поэтому последующее повышение максимума не лечит/не восстанавливает уже записанный ресурс. Все токены одного персонажа используют общий остаток. Ноль HP пока не выводит из боя автоматически.

Максимум HP задаётся полем **«Показатель максимума HP»** в «Правилах», ОД — существующим бюджетом движения. R Prison использует `hp_max` и `ap_max`. Старые определения без настройки HP получают `hp_max`, если такой ключ есть и он не используется для ОД; остальные системы требуют явного выбора. Характеристики и максимумы по-прежнему рассчитываются из правил партии, снаряжение пока не накладывает модификаторы.

### Начало и порядок боя

1. В режиме игры выберите участников в блоке «Бой», либо нажмите «Выбрать всех на текущем поле». Можно включить персонажей/NPC без токенов; несколько токенов не создают повторных участников.
2. Введите числовую инициативу вручную. Формула броска не назначается: исходные материалы её не определяют. По умолчанию список сортируется по убыванию, равные значения сохраняют порядок. Отключите сортировку для исходного порядка и используйте ↑/↓ после начала для ручной перестановки.
3. Выберите восстановление ОД и нажмите **«Начать бой»**. Нужен корректный показатель бюджета движения для всех участников. Бой включает расход ОД, первый участник начинает раунд 1.
4. **«Следующий ход»** передаёт ход следующему; после последнего начинается новый раунд. Текущий участник выделен в очереди и на всех своих токенах. Двигаться по пути может только он; для свободной расстановки остальных используйте режим мастера.
5. ↑/↓ сохраняют текущего участника и потраченные ресурсы. После изменения порядка следующие ходы идут по новому списку, поэтому мастер может вручную изменить, кто ещё успеет походить в этом раунде.

### Восстановление и сохранение

- **В начале своего хода**: восстанавливаются ОД входящего участника, включая первый ход боя.
- **В начале раунда**: восстанавливаются ОД всех участников, включая начало раунда 1.
- **Только вручную**: начало боя и переходы ничего не восстанавливают.

HP и счётчики способностей не восстанавливаются автоматически. Открытие карточки/файла, перестановка очереди, смена поля или конфигуратора не запускают начало хода повторно. Можно изменять характеристики и снаряжение в конфигураторе; удаление участника и смена ключа бюджета ОД запрещены до завершения боя, чтобы очередь не потеряла ссылки.

**«Завершить бой»** закрывает очередь, сохраняя HP, ОД, позиции и вещи, и возвращает предыдущее состояние переключателя тактического движения. Сохранение остаётся ручным — «Сохранить как…». JSON **v14** хранит участников, инициативу, порядок, текущий ход/раунд и настройку восстановления. Старые v1–v13 мигрируют без активного боя и без сброса ресурсов; оставьте резервную копию перед сохранением в новом формате. При переносе персонажа проверяется также совпадение настройки HP. Бой между партиями не переносится.
