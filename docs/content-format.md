# Импорт персонажей/NPC и предметов

Скопируйте `examples/content-template.json`, откройте в Блокноте, заполните и сохраните как UTF-8 с расширением `.json`. Не добавляйте комментарии и лишние запятые. Имена полей/коды типов оставляйте на английском, названия и описания могут быть русскими.

В приложении откройте «Предметы» либо «Персонажи» → «Выбрать JSON для импорта…». После проверки появятся имена и количество объектов. Нажмите «Добавить импорт в партию», затем сохраните партию обычной кнопкой. Отмена/ошибка ничего не добавляет. Можно загрузить только персонажей (`items: []`) или только предметы (`characters: []`), но файл не должен быть полностью пустым.

## Структура

```json
{
  "format": "rprison-content",
  "version": 1,
  "characters": [
    {
      "name": "Охранник",
      "kind": "npc",
      "footprint": { "width": 1, "height": 1 },
      "portrait": null,
      "values": { "strength": 8, "dexterity": 6, "constitution": 7, "charisma": 4, "level": 1, "armor": 0 }
    }
  ],
  "items": [
    {
      "name": "Мой предмет",
      "category": "other",
      "description": "Описание",
      "damageDice": null,
      "maxDurability": 100,
      "maxCharges": 0,
      "image": null
    }
  ]
}
```

| Поле | Что писать |
|---|---|
| `format` / `version` | Строго `"rprison-content"` и число `1` |
| `characters[].name` | Имя, 1–120 символов |
| `kind` | `"character"` — персонаж, `"npc"` — NPC |
| `footprint.width` / `height` | Целое число клеток от 1 до 10 |
| `values` | Числа по ключам **исходных** показателей применённых правил партии; допустимо `{}` для значений по умолчанию |
| `portrait` | `null` без изображения, либо PNG data URL, см. ниже |
| `items[].name` | Название шаблона, 1–120 символов |
| `category` | `"weapon"`, `"armor"`, `"consumable"`, `"other"` |
| `description` | Описание, до 2000 символов |
| `damageDice` | `null` или строка вида `"1d6"`, `"2d6+1"`; 1–99 костей, 2–1000 граней, необязательный целый модификатор |
| `maxDurability` / `maxCharges` | Целые 0–100000. Ноль означает, что ресурс не используется |
| `image` | `null` без фото или PNG data URL |

Для готового R Prison ключи исходных характеристик: `strength`, `dexterity`, `constitution`, `charisma`, `level`, `armor`. Не включайте вычисляемые `hp_max`, `ap_max` и бонусы: они пересчитаются автоматически. При собственных правилах посмотрите их ключи во вкладке «Правила». Неизвестный/вычисляемый ключ блокирует добавление всего пакета. Проверяются ключи и типы, а не смысл разных систем. Неподанные значения берутся из умолчаний партии; ограничения распределения очков R Prison пока не проверяются.

## Картинки

Проще оставить `portrait`/`image` равными `null`, а фото добавить через интерфейс. У персонажа портрет сейчас выбирается при создании; для импортируемого персонажа с фото используйте data URL в JSON.

При заполнении изображения строкой нужен формат `data:image/png;base64,` и затем содержимое PNG в base64 (вся строка в кавычках). Размер изображения — до 512×512, строка — до 2 МБ. Пути вроде `C:\photos\sword.png`, URL сайтов, SVG и JavaScript не принимаются. Фото предмета через интерфейс можно загрузить из PNG/JPG до 15 МБ: программа уменьшит его до 512 пикселей и встроит в файл партии.

## Что произойдёт

- Импорт **добавляет** объекты, не перезаписывает по имени. Повторный импорт создаёт новые копии с новыми UUID.
- Предметы из `items` становятся **шаблонами**, а не выданными экземплярами. После импорта распределите их во вкладке «Инвентари».
- NPC/персонажи не размещаются на карте автоматически. Их можно поставить обычной кнопкой «На карту».
- Версия правил, ресурсы текущего боя, способности, эффекты, токены, владельцы предметов и камеры этим форматом не переносятся.
- Максимум файла: 10 МБ, до 200 персонажей и 200 шаблонов. Общие пределы партии также проверяются (200 персонажей/200 шаблонов/1000 экземпляров). Весь импорт добавляется одной операцией или не добавляется вообще.
- Не включайте UUID, revision или неизвестные поля. Никакой исполняемый код из JSON не запускается.
