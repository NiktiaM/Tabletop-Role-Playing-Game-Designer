# Архитектура

## Текущая итерация

main: системные диалоги, проверка файлов и атомарная замена через временный файл в том же каталоге. preload: только create/save/open/importMap. renderer: формы, состояние и PixiJS-поле без доступа к Node.js. shared: схема v3 и миграции v1/v2.

Campaign v3 дополняет метаданные массивом maps и отдельным view={activeMapId,cameras}. Map содержит UUID, название, width/height исходного изображения и data URL (только PNG/JPEG base64). Камера хранит x/y в пикселях поля и zoom; размер изображения не меняется. У каждой карты своя камера. Встроенные изображения обеспечивают переносимость одного JSON без ссылок на исходные файлы. Это промежуточный формат до внедрения SQLite/ZIP, а не готовый формат пакетов правил.

Импорт проверяет объём, сигнатуру PNG/JPEG, декодирование nativeImage, размеры. Открытие и сохранение также декодируют изображения и сравнивают размеры. До 20 карт, 15 МБ импортируемого изображения, до 8192 по стороне и 32 млн пикселей; партия до 100 МБ. При невалидном файле текущая партия не заменяется. v1 мигрирует в память без изменения исходного файла; сохранение пишет v3.

PixiJS управляет отдельным canvas. Зум сохраняет точку под курсором; кнопка вписывания центрирует изображение. ResizeObserver обновляет размер рендера, камера сохраняется. Ресурсы canvas/текстуры освобождаются при переключении. Официальный модуль pixi.js/unsafe-eval заменяет динамическую генерацию функций интерпретатором для строгой CSP; разрешение unsafe-eval в CSP **не добавлено**. Предусмотрено сообщение об ошибке рендера. Графическая производительность на Windows ещё не измерялась.

Сохранение ручное; создание, импорт и изменения камеры помечают партию несохранённой. При закрытии или замене есть предупреждение. Автосохранения и резервных копий пока нет.

## Реализация сетки (итерация 3)

Каждая Map содержит grid={cellSizePx,originPx:{x,y},visible}. Координаты — пиксели исходного изображения. Новая/старая карта без сетки получает размер 64, начало (0,0), visible=false. Отдельный view.cameras не меняет калибровку. v1/v2 преобразуются в память без записи исходного файла; сохранение пишет v3.

Геометрия в domain/grid.ts не зависит от React/Electron/PixiJS: преобразования screen↔image, image→cell через floor, cell→origin. Отрицательные номера клеток допустимы до начала сетки. Линии повторяются в обе стороны от origin, ограничены пересечением изображения и viewport. Pixi Graphics рисует их после карты толщиной 1 экранный пиксель. Геометрия пересчитывается при калибровке, камере и размере viewport, без повторной загрузки изображения. Если cellSizePx*zoom<6, линии временно не рисуются и UI объясняет причину; параметры не меняются.

Поля чисел применяются кнопкой после проверки диапазонов: 4–4096 для размера, ±8192 для origin. Дробные значения поддерживаются. Флаг видимости применяется сразу. Несохранённые изменения отмечаются как обычно. Изменение размера или origin не меняет камеры.

## Целевая модель (предложение)

Campaign: снимок Ruleset, сцены, персонажи. Scene: Map, токены, геометрия, зоны. Map: изображение и Grid. Token: Character, клетка и занимаемая область. StatBlock: исходные характеристики и текущие ресурсы; производные значения вычисляются. ItemTemplate и ItemInstance разделены. EffectDefinition задаёт механику, Effect — активный экземпляр. Encounter хранит участников, инициативу, порядок и раунд. Ruleset версионирует характеристики, ресурсы, формулы и действия.

Команды проходят прикладной слой, независимое ядро выдаёт результат, события и объяснение. Состояние и журнал сохраняются транзакцией. Отмена возвращает исходное состояние, результаты бросков сохраняются. Генератор случайных чисел подменяемый.
Сетка: cellSizePx и originPx в координатах исходного изображения. image=(screen-cameraOffset)/zoom; cell=floor((image-origin)/cellSize). Камера хранится отдельно. Стены — отрезки в координатах изображения. Для крупных текстур понадобится уменьшенная копия или разбиение.

Редактор формул использует ограниченное дерево выражений, проверяет ссылки, типы, циклы и сложность. Модификаторы: исходные изменения → производные формулы → модификаторы результата → ограничения. Сложение/замена эффектов и триггеры задаются явно; цепочки ограничены.

Предлагаемое полное хранение: SQLite с миграциями, assets по хешу, штатные backup, переносимый ZIP. До миграции резервная копия; импорт ограничивает размеры и пути, проверяет ссылки и совместимость. Изменение каталога не обновляет партии молча.

Папки будущих модулей: application/, domain/{model,rules,movement,combat}, infrastructure/{storage,assets,migrations}; renderer/{panels,editors,board}. PixiJS подключён во второй итерации.
